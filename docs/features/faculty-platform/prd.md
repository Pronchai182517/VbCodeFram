# Product Requirements Document (PRD)
## เว็บไซต์คณะและระบบบริหารจัดการครบวงจร (Faculty Web Platform)

- **เวอร์ชัน:** 1.0.0
- **สถานะ:** Approved Blueprint
- **สถาปัตยกรรม:** Next.js 16 (App Router), Prisma 6 (PostgreSQL), Modular Monolith, Tailwind CSS 4 (Liyon Design System)
- **ขอบเขต:** ครอบคลุม 5 โมดูลหลัก (News, Personnel, Curriculum, Documents, Booking)

---

## 1. วัตถุประสงค์ของระบบ (Objective)

พัฒนาแพลตฟอร์มสารสนเทศระดับคณะที่รวมศูนย์การสื่อสารภายนอก (Public Portal) และการดำเนินงานภายใน (Admin Back-office Console) เข้าด้วยกันอย่างมีประสิทธิภาพ โดยมีเป้าหมายหลัก 3 ประการ:
1. **Public Information Hub:** นำเสนอข่าวสาร ข้อมูลหลักสูตร และทำเนียบคณาจารย์แก่นักเรียน นักศึกษา และประชาชนอย่างเป็นมืออาชีพ รองรับ 2 ภาษา (ไทย/อังกฤษ)
2. **Internal Process Digitalization:** ปรับกระบวนการขออนุมัติเอกสารภายในและกระบวนการจองห้องประชุม/ยานพาหนะให้เป็นรูปแบบดิจิทัล (Paperless & Automated Workflow) ตรวจสอบย้อนหลังได้ 100%
3. **Multi-Tenancy & Data Security:** รองรับการแยกข้อมูลของแต่ละภาควิชา/หน่วยงานย่อยอย่างปลอดภัยภายใต้โครงสร้างองค์กรเดียว

## 2. กลุ่มผู้ใช้งาน (User Personas & Roles)

| Persona / บทบาท | คำอธิบายและหน้าที่ในระบบ | ขอบเขตการเข้าถึง |
| :--- | :--- | :--- |
| **Guest / ประชาชนทั่วไป / นักศึกษา** | บุคคลภายนอกที่ต้องการอ่านข่าวสาร ค้นหาข้อมูลอาจารย์ที่ปรึกษา และศึกษาโครงสร้างหลักสูตร | Public Portal เท่านั้น (`/`, `/news`, `/personnel`, `/curriculum`, `/calendar`) |
| **Faculty Staff / อาจารย์และเจ้าหน้าที่** | บุคลากรของคณะที่ต้องการแก้ไขข้อมูลโปรไฟล์ตนเอง, ยื่นคำขออนุมัติเอกสาร, และขอจองห้องประชุม/รถตู้คณะ | Public Portal + Admin Console พื้นฐาน (`/me`, `/admin/documents`, `/admin/bookings`) |
| **Approver / ผู้บริหาร (หัวหน้าภาค, รองคณบดี, คณบดี)** | ผู้มีอำนาจพิจารณาและลงนามคำขอเอกสารราชการ, การเบิกจ่ายงบประมาณ, และคำขอลา | Admin Console ส่วนการอนุมัติ (`/admin/documents/approvals`) |
| **Facility Manager / เจ้าหน้าที่อาคารและยานพาหนะ** | ผู้ดูแลตารางการใช้ห้องประชุมและรถยนต์ จัดคิวคนขับ และอนุมัติคำขอจอง | Admin Console จัดการทรัพยากร (`/admin/bookings/manage`) |
| **PR & Academic Staff / เจ้าหน้าที่ประชาสัมพันธ์และบริการการศึกษา** | ผู้สร้างเนื้อหาข่าวสาร ประกาศจัดซื้อจัดจ้าง และอัปเดตเล่มหลักสูตรการศึกษา | Admin Console จัดการข่าวสารและหลักสูตร (`/admin/news`, `/admin/curriculum`) |
| **Super Admin / ผู้ดูแลระบบเทคโนโลยีสารสนเทศ** | ดูแลบัญชีผู้ใช้งาน สิทธิ์การเข้าถึง (RBAC) ภาควิชา และ Audit Logs | เข้าถึงได้ทุกฟังก์ชันในระบบ (`/admin/*`) |

## 3. รายละเอียดคุณสมบัติและ Functional Requirements (ทั้ง 5 โมดูล)

### โมดูลที่ 1: ระบบจัดการข่าวสารประชาสัมพันธ์ (News & Announcements)
- **REQ-NEWS-01 (หมวดหมู่และภาษา):** รองรับ 4 หมวดหมู่ (ทั่วไป, กิจกรรม, วิชาการ/วิจัย, ประกาศทางการ) และจัดเก็บเนื้อหา 2 ภาษา (TH/EN) พร้อม `slug` ที่เป็น URL-friendly
- **REQ-NEWS-02 (การแสดงผลหน้าบ้าน):** หน้าบ้านแสดงข่าวเด่นแบบ Carousel Banner, การ์ดข่าวแบบ Grid พร้อมแบ่งหน้า (Pagination), ตัวกรองหมวดหมู่ และช่องค้นหา Full-text
- **REQ-NEWS-03 (ระบบไฟล์แนบ):** รองรับการอัปโหลดไฟล์ประกาศ PDF และภาพประกอบ โดยแสดงปุ่มดาวน์โหลดและขนาดไฟล์ชัดเจน
- **REQ-NEWS-04 (สถิติการเข้าชม):** เพิ่มจำนวน `viewCount` เมื่อมีการเปิดอ่านเนื้อหาข่าว โดยไม่บล็อกเวลาในการโหลดหน้าแรก

### โมดูลที่ 2: ระบบจัดการบุคลากร (Faculty & Staff Directory)
- **REQ-PERS-01 (ทำเนียบผู้บริหาร):** แสดงทำเนียบคณะผู้บริหารตามลำดับตำแหน่งบริหาร (`orderIndex`) จากระดับคณบดี รองคณบดี และผู้ช่วยคณบดี
- **REQ-PERS-02 (การจำแนกตามภาควิชา):** จัดกลุ่มบุคลากรตามสังกัดภาควิชา/ศูนย์วิจัย มีตัวกรองค้นหาตามชื่อ ความเชี่ยวชาญ และหมายเลขห้องพัก
- **REQ-PERS-03 (โปรไฟล์บุคลากร):** แสดงภาพถ่าย, ตำแหน่งทางวิชาการ (ศ., รศ., ผศ., อ.), คุณวุฒิการศึกษา, ประวัติงานวิจัย และช่องทางติดต่อทางการ
- **REQ-PERS-04 (การจัดการตนเอง):** อาจารย์สามารถเข้าสู่ระบบเพื่ออัปเดตข้อมูลการติดต่อและความเชี่ยวชาญของตนเองได้

### โมดูลที่ 3: ระบบจัดการหลักสูตร (Curriculum & Courses)
- **REQ-CURR-01 (ระดับการศึกษา):** รองรับหลักสูตรระดับปริญญาตรี ปริญญาโท และปริญญาเอก
- **REQ-CURR-02 (ข้อมูลหลักสูตร):** แสดงชื่อหลักสูตร (TH/EN), จำนวนหน่วยกิตรวม, แผนการศึกษา, ค่าธรรมเนียมการศึกษาต่อภาคเรียน และแนวทางการประกอบอาชีพ
- **REQ-CURR-03 (โครงสร้างหมวดวิชา):** แสดงรายละเอียดรายวิชาแยกตามหมวดหมู่วิชา (ศึกษาทั่วไป, วิชาเฉพาะ, วิชาเลือกเสรี) พร้อมรหัสวิชาและหน่วยกิตคำบรรยาย/ปฏิบัติ
- **REQ-CURR-04 (ดาวน์โหลด มคอ.2):** มีปุ่มดาวน์โหลดเอกสารหลักสูตรฉบับสมบูรณ์ (PDF Leaflet)

### โมดูลที่ 4: ระบบบริหารจัดการและอนุมัติเอกสาร (Document Workflow & Approval)
- **REQ-DOC-01 (แบบฟอร์มคำขอ):** รองรับคำขอ 4 ประเภท (คำขอลา, ขออนุมัติเบิกจ่าย, ร่างหนังสือราชการ, เสนอโครงการ) พร้อมแนบไฟล์หลักฐาน
- **REQ-DOC-02 (เลขรับ-ส่งหนังสืออัตโนมัติ):** ออกหมายเลขติดตามเอกสาร (Tracking Number เช่น `DOC-2026-0001`) อัตโนมัติในระดับ Database Transaction
- **REQ-DOC-03 (Multi-step Sequential Route):** เอกสารวิ่งตามลำดับขั้นการอนุมัติ (Step 1 ➔ Step 2 ➔ Step 3) โดยขั้นถัดไปจะเห็นเอกสารต่อเมื่อขั้นก่อนหน้าอนุมัติแล้วเท่านั้น
- **REQ-DOC-04 (Action & Feedback):** ผู้อนุมัติสามารถกด "อนุมัติ" หรือ "ตีกลับ/ปฏิเสธ" พร้อมกรอกความเห็นประกอบ
- **REQ-DOC-05 (Audit Trail):** บันทึกประวัติการกระทำ เวลา และ IP Address ลง `audit_logs` ทุกครั้งที่มีการเปลี่ยนสถานะ

### โมดูลที่ 5: ระบบจองห้องประชุมและยานพาหนะ (Resource Booking System)
- **REQ-BOOK-01 (ทะเบียนทรัพยากร):** บันทึกข้อมูลห้องประชุม (ความจุ, โปรเจกเตอร์, ไมโครโฟน) และยานพาหนะ (รถตู้, รถบัส, พนักงานขับรถ)
- **REQ-BOOK-02 (ปฏิทินแสดงความว่าง):** ปฏิทินแสดงช่วงเวลาที่ถูกจองแล้วแบบ Real-time เพื่อป้องกันการยื่นคำขอซ้ำซ้อน
- **REQ-BOOK-03 (ตรวจจับการชนกันของเวลา - Conflict Detection):** ระบบตรวจสอบทางคณิตศาสตร์ในระดับ Database Constraint ห้ามมีการจองซ้อนทับกันในทรัพยากรเดียวกัน
- **REQ-BOOK-04 (กระบวนการพิจารณา):** เจ้าหน้าที่ยานพาหนะ/อาคารสถานที่ ตรวจสอบคำขอ มอบหมายคนขับรถ และกดยืนยันหรือปฏิเสธ

## 4. เกณฑ์การตรวจรับงาน (Acceptance Criteria)

1. **ความถูกต้องทางสถาปัตยกรรม:** รัน `npm run deps:check` และต้องไม่พบ Circular Dependency หรือการเรียกข้ามโมดูลจาก `_internal/`
2. **ความปลอดภัยของข้อมูล Multi-tenancy:** คำสั่ง Query ทั้งหมดต้องถูก Scope ด้วย `tenantId` ที่สกัดจาก Session ที่ผ่านการยืนยันตัวตนเท่านั้น (`ctx.tenantId`)
3. **การรองรับสองภาษา:** ทุกข้อความบนหน้าจอต้องถูกดึงผ่าน `t("key")` จากพจนานุกรมใน `messages.ts` และวันที่ต้องแปลงเป็น พ.ศ. (TH) / ค.ศ. (EN) ถูกต้อง
4. **ความสมบูรณ์ของการทดสอบ:** ชุดการทดสอบ `npm run test` และ `npm run test:integration` ต้องผ่าน 100% ปราศจาก Error
5. **คุณภาพตามคำสั่งระบบ:** คำสั่ง `npm run check` ผ่านครบทุกขั้นตอนโดยไม่มีข้อผิดพลาด
